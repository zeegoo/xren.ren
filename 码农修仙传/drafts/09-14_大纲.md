## 第9篇 编译器对你代码做了什么

> 文件路径：docs/jindan/09-compiler.md
> 预计篇幅：4000-5000字

### 引入
> 你写 `int a = 1 + 2;`，CPU只认0和1。
> 中间发生了什么？编译器——功法翻译官。
> 修仙者用功法口诀修炼，但天地法则只认灵力波动。编译器就是把你的口诀翻译成灵力波动的人。

### 大纲

#### 2.1 编译的四个阶段——功法翻译流水线
| 阶段 | 修仙类比 | 技术环节 | 产出 |
|------|---------|---------|------|
| 词法分析 | 拆字——把口诀拆成单字 | Lexer/Scanner | Token流 |
| 语法分析 | 理句——按语法规则组装 | Parser | AST语法树 |
| 语义分析 | 明意——检查含义是否通顺 | Semantic Analysis | 带类型的AST |
| 代码生成 | 成符——翻译成天地符文 | Code Gen | 机器码/汇编 |

#### 2.2 词法分析——拆解你的功法
- Token分类：关键字、标识符、字面量、运算符
- 有限状态机（FSM）
```c
// 输入：int a = 1 + 2;
// Token流：[int] [a] [=] [1] [+] [2] [;]
```

#### 2.3 语法分析——组装语法树
- AST（抽象语法树）
- 递归下降解析
```
    赋值语句
   /        \
 int a      加法
           /    \
          1      2
```

#### 2.4 语义分析——检查功法是否合理
- 类型检查、变量是否声明、作用域

#### 2.5 代码生成——翻译成机器指令
- 寄存器分配、指令选择、优化

## 第12篇 CPU缓存三层塔

> 文件路径：docs/jindan/12-cache-tower.md
> 预计篇幅：4000-5000字

### 引入
> 筑基期讲了寄存器/缓存/内存三层丹田。金丹期要深入缓存塔内部——
> L1/L2/L3三级缓存的工作原理，缓存行、缓存一致性、伪共享。
> 这是性能优化的核心知识。

### 大纲

#### 2.1 缓存塔结构——三层修炼塔
- L1（每核独享32-64KB）/L2（每核独享256KB-1MB）/L3（所有核共享4-64MB）
- 缓存行（Cache Line，通常64字节）：缓存的最小单位
- 修仙类比：修炼塔三层，越上层越小越快，越下层越大越慢

#### 2.2 缓存命中与未命中——修炼效率
- 命中（Hit）：数据在缓存中，直接取
- 未命中（Miss）：数据不在缓存，从下层取
- 命中率影响性能百倍

#### 2.3 局部性原理——缓存为什么有效
- 空间局部性：访问了a[0]，大概率接下来访问a[1]
- 时间局部性：刚访问过的数据大概率会再访问
- 修仙类比：你正在修炼的功法（时间局部性）和旁边放着的功法书（空间局部性）

#### 2.4 缓存一致性协议——多核修炼不冲突
- MESI协议：Modified/Exclusive/Shared/Invalid
- 修仙类比：多个修炼者共享修炼塔，不能两个人同时往同一个格子放不同的东西

#### 2.5 伪共享——隐藏的性能杀手
- 两个变量在同一缓存行，不同核各自修改，导致缓存行不停失效
- 修仙类比：两个人住在同一间修炼室，互相干扰

```c
// 伪共享示例
struct { int a; int b; } data; // a和b在同一缓存行
// 线程1写a，线程2写b → 缓存行不停在两个核间同步 → 慢

// 修复：缓存行对齐
struct { int a; char pad[60]; int b; } data; // 强制a和b在不同缓存行
```

## 第13篇 线程模型与并发真相

> 文件路径：docs/jindan/13-threading-model.md
> 预计篇幅：4000-5000字

### 引入
> 你的程序只有一个CPU核心时，世界很简单。
> 但当多线程多核心出现，修仙者要分身术——一条灵识变多条。
> 然而分身之间会争抢资源、互相干扰，这就是并发编程的苦难根源。

### 大纲

#### 2.1 并发 vs 并行——分身术 vs 多人修炼
- 并发：一个CPU切换执行多个任务（分身术，看起来同时）
- 并行：多个CPU同时执行多个任务（真分身，真正同时）

#### 2.2 线程模型——三种分身术
| 模型 | 修仙类比 | 技术 | 优缺点 |
|------|---------|------|--------|
| 1:1 内核线程 | 一个灵识对应一个天道位 | pthread/OS线程 | 强但开销大 |
| N:1 用户线程 | 多个灵识共用一个天道位 | 协程/绿色线程 | 轻但不能并行 |
| M:N 混合 | 灵识和天道位灵活对应 | Go goroutine | 兼顾两者 |

#### 2.3 并发三毒——竞态/死锁/饥饿
- **竞态条件**：两个分身同时修改同一资源，结果不可预测
- **死锁**：分身A等B的资源，B等A的资源，互相等待到天荒地老
- **饥饿**：某个分身总是抢不到资源

```python
# 竞态条件示例
counter = 0
def increment():
    global counter
    for _ in range(100000):
        counter += 1  # 不是原子操作！
# 两个线程同时跑 → counter不等于200000
```

#### 2.4 锁的家族——解药与毒药
- 互斥锁（Mutex）/自旋锁（Spinlock）/读写锁
- 锁的粒度：太粗→并发度低，太细→容易死锁
- 修仙类比：锁就是"修炼密室"的门锁，有人进去别人就得等

#### 2.5 无锁编程——更高阶的修炼
- CAS（Compare-And-Swap）原子操作
- 修仙类比：不用锁门，而是用法术确保"没人先到就放进去，有人先到就重来"

- [ ] 能解释死锁的四个必要条件

## 第14篇 内存管理：堆栈的灵力分配

> 文件路径：docs/jindan/14-memory-management.md
> 预计篇幅：4000-5000字

### 引入
> 你的程序在内存里怎么存放数据？栈和堆的区别是什么？
> 为什么递归太深会栈溢出？为什么频繁malloc/free会有内存碎片？
> 内存管理是金丹期的必修功法——掌控灵力分配，方能结丹稳固。

### 大纲

#### 2.1 内存布局——程序的灵力分布图
| 区域 | 修仙类比 | 存什么 | 管理方式 |
|------|---------|--------|---------|
| 代码段 | 功法原文 | 程序指令 | 只读 |
| 数据段 | 固定灵器 | 全局变量/静态变量 | 程序启动分配 |
| 栈 | 修炼栈台 | 局部变量/函数调用帧 | 自动分配释放 |
| 堆 | 灵力矿藏 | 动态分配的内存 | 手动/GC管理 |

#### 2.2 栈——修炼栈台（FILO）
- 函数调用 = 往栈台上放一帧（参数、局部变量、返回地址）
- 函数返回 = 取走这一帧
- 栈溢出 = 栈台太高，超出限制（如无限递归）

```c
void f() { f(); } // 无限递归 → 栈溢出 → Stack Overflow
```

#### 2.3 堆——灵力矿藏（自由分配）
- malloc/free（C）/ new/delete（C++）/ GC（Java/Python）
- 内存碎片：频繁分配释放后，空闲内存被切成碎片

#### 2.4 垃圾回收——天道自动清理
- 标记-清除 / 标记-整理 / 复制算法
- GC Root：从根对象出发，不可达的对象就是垃圾
- 修仙类比：天道定期巡查修炼密室，被遗弃的灵器（不可达对象）自动回收

#### 2.5 内存泄漏——灵力流失之毒
- 分配了不释放 = 灵力持续流失
- 常见泄漏场景：循环引用、未关闭的资源、回调未注销
- 修仙类比：你开了修炼密室但忘了关门，灵力一直泄漏
