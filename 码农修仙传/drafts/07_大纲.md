## 大纲

### ① 境界标识 + 修仙引入

> 你写了一行 `open("file.txt")`，文件就打开了。
> 你觉得理所当然？不。是"天道"在帮你。
>
> 修仙世界里，天道是看不见但无处不在的规则——灵气怎么流动、功法怎么生效，都受天道约束。
> 操作系统就是计算机世界的天道。你的程序做的一切，都要经过天道允许。

#### 修仙梗
- 天道 = 操作系统内核
- 天道规则 = 系统调用、进程调度、内存管理
- 逆天 = 绕过OS直接操作硬件（root/内核态）
- 天劫 = 信号/中断

### ② 硬核主体

#### 2.1 天道的本质——操作系统在管什么

**核心知识点**：
- OS的三大职责：管理硬件资源、提供抽象接口、隔离保护进程
- 用户态 vs 内核态

**修仙类比**：

| 天道职责 | 修仙类比 | 现实 |
|---------|---------|------|
| 管理硬件资源 | 管理天地灵脉矿脉 | CPU/内存/磁盘分配 |
| 提供抽象接口 | 给修仙者提供功法接口 | 系统调用（syscall） |
| 隔离保护 | 护宗大阵隔离宗门 | 虚拟内存隔离进程 |
| 用户态 | 外门弟子，受限修炼 | 不能直接操作硬件 |
| 内核态 | 内门长老，可调动天地灵脉 | 可直接操作硬件 |

#### 2.2 天道规则一：进程调度——谁的灵力在运转

**核心知识点**：
- 进程 = 运行中的程序
- 线程 = 进程内的执行单元
- 调度算法：时间片轮转、优先级调度
- 上下文切换的开销

**修仙类比**：
- 进程 = 一个修炼者在闭关修炼
- 线程 = 一个修炼者分出多条灵识同时修炼不同功法
- 时间片 = 每人每天只能用修炼密室一炷香的时间
- 上下文切换 = 换人时要把上一个人的修炼进度记下来（寄存器/PC保存）

**代码示例**：
```python
# 进程 vs 线程
import multiprocessing, threading

# 进程：独立的修炼者，各自独立的丹田（内存空间）
p = multiprocessing.Process(target=meditate)
# 线程：同一修炼者的灵识分身，共享丹田
t = threading.Thread(target=meditate)
```

#### 2.3 天道规则二：内存管理——虚拟内存的障眼法

**核心知识点**：
- 虚拟内存：每个进程以为自己独占4GB/256TB
- 页表映射：虚拟地址→物理地址
- 缺页中断：访问的页不在内存，OS从磁盘换入
- 分页/交换：内存不够时把不用的页写到磁盘

**修仙类比**：
- 虚拟内存 = 天道给每个修仙者施加了"你独占整个灵山"的幻术
- 页表 = 幻术对照表，把"你以为的灵山位置"映射到"真实灵脉位置"
- 缺页中断 = 你去某个位置修炼，发现那里是空的，天道要从别处调灵脉过来（换页）
- OOM = 灵脉不够了，天道直接把你的修炼中断

**核心观点**：
- 程序的"内存"不是真的物理内存，是OS维护的幻觉
- 这就是为什么两个进程读写同一个地址（虚拟）不会冲突

#### 2.4 天道规则三：文件系统——灵脉的存储

**核心知识点**：
- 文件 = 磁盘上的数据块集合
- 目录 = 文件的索引结构（树形）
- inode = 文件的元数据（权限、大小、数据块指针）
- 虚拟文件系统（VFS）：统一的文件操作接口

**修仙类比**：
- 磁盘 = 灵脉矿藏（物理存储）
- 文件 = 从矿脉中开采出的一块灵石
- inode = 灵石的鉴定文书（记录大小、品质、存放位置）
- 目录 = 灵石仓库的目录索引
- VFS = 不管灵石来自哪个矿脉，统一的鉴定和使用标准

#### 2.5 天道规则四：系统调用——凡人请求天道

**核心知识点**：
- 系统调用是用户态程序请求内核服务的接口
- 常见syscall：open/read/write/exit/fork/exec/mmap
- 系统调用的开销（用户态→内核态切换）

**修仙类比**：
- syscall = 凡人向天道祈祷，天道代为执行
- 你不能自己开采灵矿（直接操作磁盘），必须向天道祈祷（调用open()）
- 天道代为操作，然后把结果给你
- 每次祈祷有消耗（上下文切换开销）

**代码示例**：
```c
// 你以为你在直接读文件
int fd = open("file.txt", O_RDONLY);
read(fd, buf, 1024);

// 实际上每次都在"祈祷天道"
// open() → syscall → 内核态 → 驱动 → 磁盘 → 返回
// read()  → syscall → 内核态 → 翻译虚拟地址 → 磁盘 → 拷贝到用户态
```
