## 大纲

### ① 境界标识 + 修仙引入

> 你在浏览器输入 `xren.ren`，0.3秒后页面出现。
> 这0.3秒里，你的电脑和千里之外的服务器完成了一次"传送"。
>
> 修仙世界里有传送阵——站在甲地阵法上，灵力一催动，人就到了乙地。
> 网络就是计算机世界的传送阵。但传送不是瞬间完成的，它有一套精密的协议。

#### 修仙梗
- 传送阵 = 网络协议
- 阵法节点 = 路由器/交换机
- 传音符 = 数据包
- 阵法分层 = OSI/TCP-IP四层模型

### ② 硬核主体

#### 2.1 传送阵的四层结构——TCP/IP模型

**核心知识点**：
- TCP/IP四层模型：应用层→传输层→网络层→链路层
- 每层职责不同，层层封装

**修仙类比**：传送阵的四个法阵层

| 层级 | 修仙类比 | 技术现实 | 职责 |
|------|---------|---------|------|
| 应用层 | 传信内容（写什么信） | HTTP/DNS/SMTP | 定义传输的内容格式 |
| 传输层 | 传信方式（挂号/平信） | TCP/UDP | 保证可靠/追求速度 |
| 网络层 | 传送路线（送到哪个城） | IP/路由 | 跨网络寻址和路由 |
| 链路层 | 实际搬运（驿站接力） | 以太网/WiFi | 物理传输 |

**数据封装过程**：
```
你发送 "Hello" →
  应用层：HTTP报文 "GET / HTTP/1.1\r\n..."
  传输层：TCP段 [源端口|目标端口|序号|HTTP数据]
  网络层：IP包 [源IP|目标IP|TTL|TCP段]
  链路层：以太网帧 [源MAC|目标MAC|IP包|CRC]
  → 通过网线/WiFi发出
```

> 配文：你以为你发了一条消息，实际上它被套了四层信封，每层信封上有不同的地址信息。

#### 2.2 TCP三次握手——为什么是三次

**核心知识点**：
- TCP连接建立：SYN→SYN-ACK→ACK
- 为什么不是两次？防止历史连接建立
- 为什么不是四次？三次已经够了

**修仙类比**：修仙者建立传音通道

| 步骤 | 修仙类比 | TCP术语 |
|------|---------|---------|
| 第一次 | "你能听到我吗？" | Client → SYN → Server |
| 第二次 | "我能听到。你能听到我吗？" | Server → SYN+ACK → Client |
| 第三次 | "我也能听到。开始传音吧。" | Client → ACK → Server |

**为什么两次不够？**
> 如果只用两次：Client发"你能听到吗？" → Server回"能" → 直接开始。
> 但如果这个"你能听到吗"是上次延迟到达的旧消息呢？Server回了"能"，但Client根本不想连接了。
> 第三次握手就是为了确认：Client确实想建立连接，不是历史消息。

#### 2.3 DNS——域名解析就是查传送阵地址簿

**核心知识点**：
- 域名→IP地址的解析过程
- DNS层级：根DNS→顶级DNS→权威DNS
- 缓存机制

**修仙类比**：
- DNS = 传送阵地址簿：你只知道"xren.ren"这个阵法名称，但传送阵需要精确的灵脉坐标（IP地址）
- 查询过程：
  1. 你问本地驿站（本地DNS缓存）
  2. 驿站不知道 → 问京城总驿（根DNS）
  3. 京城说"去问.ren省的驿"（顶级域DNS）
  4. .ren省说"xren.ren的坐标是1.2.3.4"（权威DNS）
  5. 驿站记下来（缓存），下次不用再问

#### 2.4 HTTP——传信的格式和礼仪

**核心知识点**：
- HTTP请求/响应模型
- 无状态协议 & Cookie/Session
- HTTP vs HTTPS（TLS加密层）

**修仙类比**：
- HTTP = 传信的标准格式（信封格式、收信人称谓、正文格式）
- 无状态 = 每次传信天道不会记住上次的内容，需要你自己带"身份令牌"（Cookie）
- HTTPS = 加密的传信通道，外人截获也看不懂

**代码示例**：
```http
# HTTP请求 = 一封标准格式的信
GET /index.html HTTP/1.1    ← 你要什么
Host: xren.ren              ← 收信地址
User-Agent: Mozilla/5.0     ← 你的身份
Cookie: session=abc123      ← 身份令牌

# HTTP响应 = 回信
HTTP/1.1 200 OK             ← 收到，没问题
Content-Type: text/html      ← 信的内容格式
Set-Cookie: session=abc123   ← 给你一个新令牌
```

#### 2.5 从输入URL到页面渲染——传送阵全流程

**完整流程**：
1. 输入URL → DNS解析域名→IP地址
2. TCP三次握手建立连接
3. 发送HTTP请求
4. 服务器处理请求，返回HTTP响应
5. 浏览器解析HTML，构建DOM树
6. CSS渲染，布局，绘制
7. 断开TCP连接（四次挥手）
